# 评测协议：证明产品有用，而不是证明 AI 一定获胜

## 1. 三个分别回答的问题

A. **正确性**：独立验收是否能识别已知几何风险，同时不滥拒绝安全路径？

B. **恢复**：在目标仍可达时是否能恢复；不可达时是否正确停止？

C. **Agent 增量**：同预算下，反馈驱动选例是否比固定/随机/强规则方法更有效，或者真实减少用户操作？

A/B 成立不能自动证明 C。报告必须分别回答。模型无优势时保留结果，展示产品工作流的实际边界，不编造提升。

## 2. 两条实验线

### E1：固定案例可靠性验收（P0）

先用开发例调通，冻结实现后新建至少 12 个最终小场景：3 个正常、3 个可恢复堵路、3 个净空边界、3 个不可达/应停止。每类必须包含程序化变体，最终种子不得与开发集重复。

对三类 SUT 执行同一套场景：

- 旧导航适配器（若可复现且授权允许）；
- 新实现的安全参考 A*，作为强基线；
- 显式标注的受控缺陷版本，仅用于验证检测器敏感性。

场景正确行为由生成器约束、独立几何检查和有限网格可达性 oracle 给出，不由待测导航器或 Agnes 宣布。oracle 的运动图、端点连接和无路结论边界按安全规范第 9 节；不能把某个启发式规划器失败当不可达真值。无法确定的标签为 UNKNOWN，不强行计为失败。

### E2：预算受限测试选例（P0，小规模）

每个 campaign 使用相同合法故障候选空间、同一个 SUT 版本、同一个起终点任务、同一总预算。4 种测试员：

| 方法 | 策略 |
|---|---|
| FixedCoverage | 预先登记的均衡故障覆盖顺序 |
| SeededRandom | 同一候选空间、可复现随机采样 |
| AdaptiveRule | 依据上一轮几何证据和预设严重度阶梯调整测试，不能被故意削弱 |
| AgnesAGH | 根据已返回证据自主选择下一案例、复测或结束 |

建议每方法每 campaign 12 个 SUT 执行预算，开发期 3 个种子检查可行性，最终至少 5 个未见种子的小评测；有预算再扩展。这里是规模建议，不是赛事数量要求。

一次 `run_case`、`rerun_case` 或产生新规划的恢复都计一次 SUT 执行；其后一次独立审计合并在同一评测单位。读取既有证据不计 SUT 执行，但仍受工具次数和时间预算。超时/无效执行若已占资源，仍计预算。模型请求、tokens、费用和墙钟时间另报。

合规预算不足时保留小规模结果或 NOT_RUN，不用 mock 替代真实 Agnes 比较，不为了凑样本暗中超支。

## 3. 去重、失败与人工成本

唯一失败签名预先固定，例如：`SUT版本 + failure_code + 地图族 + 违规区域/边界类别`。同一路段重复改一格不能无限计“发现新漏洞”。另报场景级失败数量和故障类型覆盖，避免指标依赖签名定义。

大模型说“这是 Bug”不是检出。候选失败需在相同配置/种子下独立重放确认；不稳定结果标记 flaky，不计为确定复现缺陷。

人工操作成本可报告完成一轮预设工作流所需点击/输入/手工编辑次数，记录操作者、条件与录像。没有真实用户对照实验，不写“节省工程师 X% 工时”。

## 4. 必须报告的指标

| 指标 | 分子/分母及限制 |
|---|---|
| 危险候选检出率 | 验收拒绝的已知危险路径 / 所有已知危险候选 |
| 安全路径误报率 | 被拒绝的已知安全路径 / 所有已知安全候选 |
| 可恢复任务到达率 | 审计通过且到达固定目标 / oracle 判可恢复任务 |
| 正确停止率 | 正确停止 / oracle 判不可达任务 |
| 误停率 | 可恢复却停止 / oracle 判可恢复任务 |
| 缺陷复现率 | 重放确认失败 / 申请复现失败案例 |
| 预算内唯一失败数 | 每 campaign 预定义去重后的可复现失败数量 |
| 首个确认失败成本 | 消耗的 SUT 次数及墙钟时间；未发现记为预算截断，不删除 |
| 额外成本 | 总 SUT 调用、审计、模型请求/tokens/成本、耗时 |

分母为 0 返回 null 并注明原因。候选路径有风险不等于真实发生碰撞；本项目必须区分二者。SAFE_STOP 不能混进到达成功率。

## 5. 冻结与统计

R06 正式运行前固定代码提交或内容快照哈希、依赖、提示词、模型路由与模型标识、场景生成器、种子规则、预算、签名定义及指标。冻结后先生成新最终种子，不看结果调策略。修改后建立新实验编号，旧结果不删除。

逐例报告原始计数与配对差异。小样本只做描述性判断；可给简单置信区间但不声称已达到工业安全可靠性。失败、超时、早停均保留。

推荐图表：每个相同 seed 下不同测试员发现的唯一失败数；累计执行预算–失败发现曲线；恢复/正确停止/误停/错误放行的计数。不得只展示最漂亮一次。

## 6. 三种可能结论都允许

- Agent 在等预算下发现更多可复现失败：报告具体条件及额外模型成本。
- Agent 与强规则相近：报告自动组织/解释/复现的产品能力，不宣称算法更强。
- Agent 更差：如实展示，保留确定性回归工具；清楚说明当前智能策略尚不成熟。

禁用“必须提升 20% 才算成功”式目标驱动造结果。执行包验收考察实验是否诚实可复现，不要求科学结论必须正向。
