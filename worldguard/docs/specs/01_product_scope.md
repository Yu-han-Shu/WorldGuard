# 冻结产品范围：不是新导航器，而是 AI 测试员

## 1. 定位

**WorldGuard — 面向室内移动机器人的 AI 导航故障测试与恢复验收工作台。**

面向高校机器人实验室及小型导航研发团队：新版本导航算法部署前，帮助开发者选择风险场景、重现失败、验证恢复，并得到可以交给同事复查的测试包。真实用户需求和节省工时仍待验证，不能称已有付费客户。

输入：场景、固定起终点、机器人足迹与安全余量、导航适配器、测试预算。

输出：每个案例的地图版本、候选路径、违规几何证据、恢复动作、确定性复现命令、批次结论，以及真实 AGH 调用轨迹。

用户体验：**选择导航器和场景 → 启动测试 → 查看失败定位 → 对比恢复 → 导出案例与报告。**

## 2. 第一版承诺

| 内容 | P0 边界 |
|---|---|
| 环境 | 单机器人平面几何仿真；网格地图，可由点云投影或自建 |
| 故障 | 临时堵路、通道净空不足、目标区域断连 |
| 动作 | 选择测试案例、读取证据、按固定条件复测、更新地图并重规划、安全停止 |
| 验证 | 当前地图上的连续线段足迹、边界、起终点、版本与约束 |
| 智能体 | Agnes 经官方 AGH 调用受控工具；反馈决定后续选例和恢复 |
| 产品 | 本地工作台、进度与路径、原始证据、JSON/Markdown 导出 |
| 复现 | 自包含小场景，无需旧仓库的大型私有资产 |

不承诺：任意机器人系统接入、机械臂、实时控制、一般动力学/制动安全、生成式世界模型、故障自动改源代码、商业云平台。

## 3. 两种模式，不要混淆

**演示/回归模式：** 确定的地图和故障序列，便于用户复现三类结果。可以证明执行闭环，不证明智能测试选例优于规则。

**主动测试模式：** 在同一受限候选空间和总调用预算下，Agnes 根据已观察到的结果选择下一案例或复测。与固定覆盖、均匀随机、反馈驱动规则三种方法对照。

第一种是产品必需；第二种才检验“为什么需要 Agent”。不能把三例预设顺序重放包装成自主探索。

## 4. 原方案如何保留

报名组别及 C/C4 保持。原始一句话创意保留在报名档案：

> 基于 Agnes + AGH 构建具身智能安全验证与故障恢复 Agent，通过数字孪生故障注入、路径风险诊断、自主重规划及独立碰撞验收，实现物理智能体的安全可靠执行闭环。

作品说明应加范围：这里的“恢复”是**离线仿真中修正地图视图、选择受支持的规划模式、复测或安全停止**，不是修复物理硬件或任何程序错误。只有自建二维地图时写“几何仿真”；有真实场景映射时才写相应的数字孪生，不冒充实景动力学。

## 5. MVP 最终通过条件

在一份可复现发布包中，别人可以启动页面、选择场景、运行真实 AGH 测试，看到可恢复失败与不可恢复失败两类结果，再下载同一 run_id 的原始案例、报告和复现方式。独立测试能验证系统拒绝危险路径，且不会靠全程停止伪装高成功率。

三类故障与启动路径做完前，不添加新场景、登录系统或三维编辑器。没有模型 Key 时应有清楚标注的离线调试模式，但不能作为参赛 LIVE 证据。
