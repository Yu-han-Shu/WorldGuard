# 工作台与路演：用户能操作，而不只是看动画

## 产品页面（P0）

一个本地页面，优先 Streamlit；沿用可用既有前端亦可，不为视觉重建复杂栈。

**顶部状态**：LIVE_AGNES / 离线规则 / MOCK / REPLAY；AGH 连接状态、导航器名称、当前 run_id、预算剩余。状态来自服务，不写死绿色标签。

**配置区**：选择内置场景、导航器、固定起终点、机器人参数、测试员类型及批准预算。默认不接受任意代码/大文件上传。运行后配置锁定，变化须新建 run。

**地图区**：原始障碍、注入障碍、固定起终点、旧路径、新路径、机器人足迹、违规线段/最近危险点。区分线型/图例，不能只靠红绿色。

**执行区**：每次真实工具调用、参数摘要、已观察证据、Agnes 选择下一操作的简短理由、错误和用量。未经核验的模型文字用“建议/推测”标记。

**结果区**：单例结果、恢复结果与批次结论分开；导出 case JSON、结果 JSON、Markdown 报告及复现命令。显示测试范围与仿真局限。

## 最短操作路径

选择内置场景 → 选择待测导航器 → “开始测试” → 查看问题及复验 → “导出证据”。可以取消；刷新页面不能重复消耗 API；同一任务按 run_id 恢复显示。

UI 不直接调用模型，不写 raw verdict。所有数据读取当前 run 的真实 artifacts；用同一个 Python 核心提供 CLI、MCP 与 UI，禁止三套行为互不一致。

## 三段必备演示

1. 正常场景：参考导航器通过，不为增加“发现问题数量”刻意误报。
2. 可恢复故障：导航器使用陈旧地图，候选路径有风险；验收指出具体线段；Agnes 选择刷新地图、重规划、复验，最终到达。
3. 不可达故障：目标通道断开；系统停止并输出原因。报告显示 `SAFE_STOP` 与“未到达”，不是“任务成功”。

陈旧地图、参考/缺陷导航器、合成场景都要显式标注。现场演示一个鲜明案例，报告另外两类的完整结果。

## 4 分钟演示结构（建议，不是官方时长细则）

- 0:00–0:30：用户痛点——导航版本上线前，怎样低成本复现风险？
- 0:30–1:00：输入地图、任务、待测导航器和测试预算。
- 1:00–2:20：真实 AGH 选例、发现风险、选择恢复并复验。
- 2:20–3:10：不可达时正确停止，展示原失败记录仍保留。
- 3:10–3:40：与固定/随机/强规则基线对照，不隐藏模型成本。
- 3:40–4:00：导出报告和复现操作，说明适用边界。

视频要求按赛事已确认通知准备；现场拆分时间以工作组最新要求为准。使用录像备份应标“录制运行/回放”，不能伪装现场实时模型推理。

## 建议的产品介绍

“WorldGuard 是机器人导航上线前的 AI 测试员。它不替代导航算法，而是通过仿真故障测试和独立几何检查，帮助开发者发现、复现并验证导航失败。首版支持一类室内平面导航任务，正在验证 AI 选例相对规则测试的价值。”

不要说：现有机器人不会避障、首次实现自动重规划、通过即实机绝对安全、已获企业认可、把所有物理故障自动修好。
