# 旧仓库的实际复用点与必须先验证的风险

静态依据见 [来源登记](06_sources_compliance.md) 的 S2/S3。本节列“已观察到的代码行为和需要测试的边界”，不把未复现疑点宣称为实际漏洞。

## 可复用部分

`navigation.py` 提供 OccupancyMap、世界/网格坐标转换、A*、路径简化、点云地面与栅格构造。可以把规划接口抽成独立适配器，Open3D 只在三维导入时使用。

`validate_outputs.py` 提供历史输出核对和度量思路，但它是针对固定数据集的验收脚本，不是通用在线安全检查器。

## 五个不能原样照搬的地方

| 静态发现 | 为什么影响 WorldGuard | 必须做的验证 |
|---|---|---|
| `_neighbors` 枚举八邻域，片段中没有检查对角两侧邻格 | 可能出现离散路径穿角边界 | 构造两格对角障碍，确认真实行为；不要凭阅读直接报漏洞 |
| `snap_to_free` 寻找最近自由格，没有在该函数内看到距离上限 | 可能把不可达目标改成其他位置 | 保存 requested/snap endpoints，按原目标容差独立判定 |
| `_largest_component` 只保留最大自由连通域 | 小区域任务可能被预处理丢失 | 多连通域输入；记录该假设，不偷偷换场景 |
| 旧验收循环主要统计导出路径点在自由格内与否 | 端点安全不能证明线段足迹安全 | 新增薄墙跨越测试和独立连续几何检查 |
| 旧脚本带固定 500 张图、5×5 路径、Windows 绝对路径等验收条件 | 无法直接作为新项目的一键验收入口 | 拆分与导航有关的代码，使用新的自包含 fixtures |

另外，原导航器的网格到世界坐标更接近格点坐标，WorldGuard 冻结规范采用 cell 中心；适配必须记录映射及偏移，不能把一组数字直接解释为另一种坐标。

## 复用不等于篡改基线

保留旧版在原假设下的行为为 `legacy_adapter`，冻结它再比较。改良版命名 `reference_safe_astar` 或明确新版本。不能悄悄修好旧版后仍将它与不同条件的旧结果比较。

如果旧依赖不可安装：先用纯二维安全参考实现完成产品，以“参考导航器”为待测对象；旧版适配标 BLOCKED。可使用有明确标签的缺陷导航器验证检测器，但不能声称这些缺陷来自原仓库。

不把 README 的 25/25 与零违规作为新系统证据，不搬运旧数据成绩，不据此预期模型必然提升。
