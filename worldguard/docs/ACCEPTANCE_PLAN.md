## 1. 验收目标与冻结范围

验收一套可操作的本地导航评测产品：输入目标与策略 → 确认计划 → 执行测试 → 查看原始失败和恢复 / 停止 → 查看报告、追问与导出证据。

保留现有视觉与报告优先布局，进入收尾阶段；只修影响正确性、流程、演示和交付的问题。反事实实验、证据护照与策略比较按实际实现验收，不额外扩展概念。单机器人二维仿真是本次范围；实机、ROS、多租户、跨地图泛化不是交付承诺。

## 5. 推荐执行顺序

1. **固定候选版本与范围**：统一当前启动入口，确认交付包文件清单。新增需求暂记后续迭代。
2. **整站核心流程**：先离线跑通正常、堵路恢复、不可达停止；再对当前界面做一轮真实 Agnes 与真实问答验收。
3. **异常与证据**：检查刷新、取消、重复提交、失败提示；核对报告、ZIP 与原始记录。
4. **干净安装和独立复核**：使用新目录与正确的发布候选；由另一位成员复核核心证据。
5. **冻结演示版本**：选择一个完整代表案例，准备真实运行录像和演示步骤；录像标注回放。完成成员、分工、声明及赛事要求核对。

技术部分由开发方执行并留证；独立复核由另一位成员 / 审查者完成；演示是否易懂以及成员与赛事材料由团队确认。未指定具体姓名前不代填负责人。

## 6. 通过与交付标准

- P0 为零，阻断核心流程或交付的 P1 已关闭；剩余限制写入交付说明。
- A01–A12 有逐项结论与证据；若主动缩减某项功能，先明确从本次交付与演示承诺中移除。
- 正常通行、堵路恢复、不可达停止均有可复核记录；原始失败保留。
- 最终代码提交号、候选包哈希、安装步骤和演示使用版本一致。
- 独立复核通过后才标记“最终技术验收通过”；材料确认后再标记“可提交”。
- 没有 E2 时允许交付产品，但不讲“已证明 Agent 优于规则”；不把二维仿真通过说成实机安全认证。

建议的演示主线：**给出仓库导航策略 → 发现堵路失败 → 查看恢复与独立验收 → 导出证据；补充不可达时正确停止。**
